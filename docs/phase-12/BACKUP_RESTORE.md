> خطة عملية: ماذا نحمي، بطبقات، بأوامر جاهزة، وبإجراء استعادة مُختبَر خطوة بخطوة.

## ما الذي نحميه

| الأصل | مكانه | الأهمية |
|---|---|---|
| `auth.users` + كل جداول `public` (المهام/العادات/اليوميات/المجتمع/الاشتراكات…) | Supabase Postgres | **حرجة** — مصدر الحقيقة الوحيد |

| متغيرات البيئة | Vercel / Supabase / Upstash | **حرجة** — أسرار لا تُستعاد من الكود؛ احتفظ بنسخة مشفرة لدى المالك |

## الطبقات

### الطبقة 0 — الآن (خطة Supabase المجانية)

> ⚠️ **الخطة المجانية لا تتضمن أي نسخ احتياطي تلقائي** — لا شيء يحمي
> البيانات اليوم إلا ما نفعله بأيدينا.

- [ ] **dump يدوي أسبوعي** (الأمر بالأسفل) + حفظ النسخة خارج الجهاز
      (Drive / تخزين مشفّر) — الالتزام يوم ثابت كل أسبوع
- [ ] **قبل أي هجرة كبيرة**: dump فوري قبل التشغيل مباشرة
- [ ] تصدير المستخدم الذاتي متاح دائمًا: `/api/rise/export` (بياناته JSON)

### الطبقة 1 — قبل الإطلاق العام (Supabase Pro)

- [ ] نسخ يومية تلقائية (تحتفظ 7 أيام) — تُفعّل تلقائيًا بالترقية
- [ ] **Point-in-Time Recovery (PITR)** — استعادة لأي لحظة خلال آخر
      7 أيام؛ يُفعّل من Dashboard → Database → Backups
- [ ] أرشفة أسبوعية إضافية: dump يدوي يُحفظ 30 يومًا (تاريخ مسؤول)

### الطبقة 2 — المستخدم (self-service)

- تصدير بياناته: `/api/rise/export` (بمعدل 5/دقيقة)
- حذف حسابه قاطعًا: `/api/auth/delete-account` — `ON DELETE CASCADE`
  يمتد لكل جداوله

## أوامر النسخ (جاهزة للنسخ)

```bash
# 1) ربط المشروع (مرة واحدة)
supabase login
supabase link --project-ref cxtevczaptludomuiemq

# 2) dump كامل (schema + data + roles) — ملف واحد مؤرخ
supabase db dump -f awj-backup-$(date +%Y%m%d-%H%M).sql

# 3) تحقق نزاهة اختياري (sha256 بجانب الملف)
sha256sum awj-backup-*.sql > awj-backup-$(date +%Y%m%d).sha256
```

## إجراء الاستعادة (خطوة بخطوة)

1. **لا تتصرف متسرعًا** — حدد النطاق أولًا: صفوف؟ جدول؟ القاعدة كلها؟
   (الاستعادة الانتقائية أسرع وأأمن من الكاملة).
2. **أوقف النزيف إن كان الخلل مستمرًا**: الحالات القصوى — إيقاف المشروع
   مؤقتًا من لوحة Supabase أو تجميد النشر من Vercel؛ الخلل المحدود لا
   يستدعي شيئًا من ذلك.
3. **للخلل المحدود** (صفوف/جدول): استورد آخر dump داخل مشروع Supabase
   **مؤقت**، استخرج الصفوف المطلوبة، ثم نفّذ INSERTs/UPDATEs الدقيقة في
   الإنتاج عبر SQL Editor — لا تستبدل قاعدة كاملة لصف واحد.
4. **للكوارث الشاملة**: مشروع Supabase جديد → تشغيل الهجرات بالترتيب
   (001→034) → استيراد dump البيانات → تحديث متغيرات Vercel
   (`NEXT_PUBLIC_SUPABASE_URL` / `ANON` / `SERVICE_ROLE`) → نشر جديد.
5. **تحقق بعد الاستعادة** (smoke): تسجيل دخول + إنشاء مهمة + منشور مجتمع
   + صفحة الاشتراكات — كلها تعمل.
6. **وثّق الحادث** في `docs/worklogs/worklog.md`: السبب الجذري، النطاق،
   والزمن من الكشف حتى العودة.
