## 2. الأخطاء الحقيقية التي كسرتها QA (وأُصلحت)

### الخطأ 1 — حذف الحساب لم يكن يعمل إطلاقًا ❌→✅
- **العَرَض:** `DELETE /api/auth/delete-account` يرجع 500 والحساب لا يُحذف.
- **الجذر:** `admin.auth.deleteUser(userId)` — الدالة موجودة على `auth.admin` وليس `auth` مباشرة → الاستدعاء = `undefined(...)` → TypeError. اختبارات tsc لم تلتقطها لأن كاش supabase-js كان `any` (أصلحناه بالت typing).
- **الإصلاح:** `admin.auth.admin.deleteUser(userId)` + تتبع خطوات في السجل (commit b772388).

### الخطأ 2 — إبطال الجلسات بعد كلمة المرور/الحذف كان صامت الفشل ❌→✅ (أمني)
- **العَرَض:** `admin.auth.signOut(userId)` في 3 مسارات (delete-account · update-password · logout-all).
- **الجذر:** admin signOut يستقبل **JWT** لا userId — الخادم كان يتجاهل الطلب (401) ويُهمل، فتبقى كل الجلسات صالحة بعد تغيير كلمة المرور أو حذف الحساب.
- **الإصلاح:** `admin.auth.admin.signOut(accessToken)` — جلسات المستخدم تُبطل فعليًا الآن (متحقق: الجلسة القديمة ترجع 401 بعد الحذف).

### الخطأ 3 — مستخدمو المجتمع لا يمكن حذفهم نهائيًا ❌→✅ (هجرة 036 مطبقة ومتحقق منها)
- **العَرَض:** الحساب الذي له أي نشاط مجتمع (كل منشور/تعليق/تفاعل/بلاغ يكتب صف audit_logs) — حذفه يفشل بـ «Database error deleting user».
- **الجذر:** `audit_logs.actor_user_id → profiles ON DELETE RESTRICT` (هجرة 013) — قيد أمني مقصود لكنه يقفل حذف الحساب.
- **الحل:** هجرة **036_qa_account_delete_fix.sql**: السجل يبقى والفاعل يُجهَّل (SET NULL + nullable) + نفس معالجة مراجع الإشراف الثلاثة.
- **✅ التحقق الحي (2026-09-14 جلسة 2):** المالك طبق الهجرة — حذف حساب له منشور مجتمع + بلاغ ضده = **200**، وحذف الحساب التجريبي العالق `qa-cycle-1789343456@qa-probe.test` (أسوأ حالة) = **200** وجلساته ميتة بعدها.

## 3. حدود الـRate-Limit: التشخيص النهائي بعد إعادة النشر 🔴👤
- **الحالة:** المالك ربط Upstash (الخطة المجانية) 2026-09-14 — لكن **المتغيرين غير فعّالين في بيئة Production حتى بعد deploy جديد** (اختبار 7 محاولات دخول باتصالات منفصلة بعد إعادة النشر: كلها 401 بلا 429).
- **التشخيص القاطع (اختبار burst باتصال واحد keep-alive):** المحاولة 6 و7 → **429 «تجاوزت الحد المسموح من الطلبات»** — أي أن **كود الحدود يعمل 100%** والعداد يتراكم داخل نفس العزل؛ ما ينقص هو العدّ الموزع عبر النسخ (Upstash) لأن كل اتصال جديد يهبط على عزل مختلف فيصفّر العداد.
- **الإصلاح الدقيق (Vercel Dashboard → مشروع rise-os → Settings → Environment Variables):**
  1. أضف المتغيرين **بالأسماء الحرفية**: `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN`
  2. القيم من Upstash Console → قاعدة Redis → **REST API** (الرابط بصيغة `https://…upstash.io` + التوكن — **ليس** رابط `redis://` العادي)
  3. Environment = **Production** (أو All) — وليس Development فقط
  4. **Deployments → أحدث نشر → ⋯ → Redeploy** (متغيرات البيئة لا تُفعَّل إلا بنشر جديد)
- **التحقق النهائي بعد التنفيذ:** 6 محاولات دخول خاطئة **باتصالات منفصلة** (كل محاولة في طلب جديد) → المحاولة السادسة = 429. اختبار المتصفح وحده غير حاسم (اتصال واحد = نفس العزل = 429 يظهر حتى بدون Upstash).
