## 2. رحلات المستخدم الخمس (User Journeys)

كل رحلة تبدأ من «الدخول البارد» وتُقاس بعدد النقرات حتى إنجاز القصد الأساسي. الأرقام الحالية **مُقيَّمة من قراءة الكود**، والأرقام الهدف هي عقد المرحلة 17/18.

### 2.1 مستخدم جديد («أول 5 دقائق»)
```
Landing → (تسجيل/دخول query-mode) → Onboarding (4 خطوات: أهلاً بك → يومك مع أوج → استكشف الوحدات → نصائح سريعة)
→ Home بحالة «يوم فارغ» ودعوة واحدة واضحة → Quick Add أول مهمة → أول احتفال صغير (لا مفرطًا)
```
- **الهدف:** أول قيمة (مهمة/عادة/يومية) خلال ≤ 3 نقرات بعد الـ Onboarding.
- **قاعدة اليوم الفارغ:** Home الجديد لمستخدم بلا بيانات = دعوة واحدة («ابدأ يومك») + 3 قوالب بداية، لا شبكة 20+ بطاقة.

### 2.2 المستخدم اليومي («صباح 30 ثانية»)
```
افتح التطبيق → Home (تحية + لقطة اليوم + تركيز اليوم) → علِّم عادة من لقطة اليوم مباشرة → ابدأ أول مهمة/تركيز
```
- **الهدف:** فهم اليوم خلال ≤ 5 ثوانٍ بدون فتح أي وحدة (بوابة إغلاق المرحلة 17).
- المساء: إغلاق اليوم من نفس الشاشة (مراجعة سريعة: ما تبقّى → الفرصة التالية).

### 2.3 مستخدم التعلم («جلسة نمو»)
```
Home → «أكمل من حيث توقفت» (بطاقة التعلم تظهر فقط إن كان هناك تقدم حقيقي) → وحدة التعلم → إنهاء جلسة → عودة تلقائية للـ Home
```
- **القاعدة:** بطاقات Continue لا تُخترع؛ تظهر فقط عند وجود جلسة/فصل/مورد متوقف فعليًا.

### 2.4 مستخدم التركيز («أريد جلسة عمق الآن»)
```
Home → «تركيز اليوم: ابدأ» (أو زر + → جلسة تركيز) → شاشة العمل العميق الغامرة → انتهاء الجلسة → تسجيل سريع للنتيجة
```
- **الهدف:** من فتح التطبيق إلى بدء المؤقت ≤ نقرتين.
- شاشة التركيز **غامرة**: تخفي كل شيء غير المؤقت والمهمة المرتبطة (Phase 19).

### 2.5 مستخدم Max يريد MCP
```
حسابي → قسم MCP (داخل الإعدادات حاليًا) → توليد/نسخ المفتاح → لصقه في عميل MCP (JSON جاهز / Claude Code)
```
- المرحلة 26 تنقل هذا إلى صفحة `/mcp` مستقلة بحالة اتصال وسجل آخر 10 عمليات. الرحلة هنا موثّقة لضمان أن العوالم لا تبتلع هوية MCP التقنية.

## 3. العوالم الأربعة (Life Worlds)

التقسيم الحالي في الشريط (اليوم/التنفيذ/النمو/المجتمع/الحياة) جيد لكنه **مبني على نوع النشاط لا على معنى الحياة**، والمجتمع لا يستحق أن يكون «عالمًا» كاملًا بصريةً. التقسيم الجديد:

### 3.1 الخريطة النهائية

| العالم | المعنى (سؤاله) | الوحدات (6/3/4/5 = 18) |
|---|---|---|
| **أنجز** 🔥 | «ماذا أنجز اليوم؟» — التنفيذ والإنتاج | `tasks` · `projects` · `goals` · `deepwork` · `work` · `calendar` (6) |
| **تطور** 🌱 | «كيف أنمو؟» — التعلم والمعرفة | `learning` · `reading` · `brain` (3) |
| **توازن** ⚖️ | «هل أنا متوازن؟» — الجسد والروتين والتأمل | `morning` · `habits` · `journal` · `health` (4) |
| **إدارة حياتي** 🧭 | «أدير حياتي» — التخطيط والمال والقياس | `planner` · `finance` · `analytics` · `weekly-review` · `monthly-review` (5) |

**خارج العوالم (هوية مستقلة):**
- `dashboard` → **الرئيسية** (Home — عمود اليوم، ليس داخل أي عالم)
- `community` → **المجتمع** (نقطة تنقل مستقلة في الجوال)
- `settings` → **حسابي** (نقطة تنقل مستقلة في الجوال)
- `admin-panel` → أدوات الإدارة (يظهر للأدمن فقط، خارج العوالم)

**التحقق الحسابي:** 6+3+4+5 = 18 + 4 وحدات نظام = 22 ✓ (يطابق `ModuleId` بالضبط — لا وحدة ساقطة ولا مكررة).

### 3.2 قواعد العوالم
1. العوالم هي **مستوى تجميع عرضي** فقط — لا تغيّر مسارات بيانات ولا صلاحيات ولا `ModuleId`.
2. ترتيب الظهور: أنجز → تطور → توازن → إدارة حياتي (ترتيب الاشتغال النفسي اليومي).
3. كل عالم له **لون هوية واحد** (نقطة اللون في الشريط) مشتق من الـ tokens الحالية (`emerald-accent`, `gold`, `forest`, `rose-accent` الموجودة فعلًا في dashboard.tsx).
4. لا يظهر وصف تسويقي للعالم — سطر واحد فقط («عالم الإنجاز والتنفيذ»).

### 3.3 جدول إعادة التوطين (من المجموعات الحالية إلى العوالم)

| المجموعة الحالية | الوحدات | المصير |
|---|---|---|
| «اليوم» (today) | morning, planner, habits, journal | morning/habits/journal → **توازن** · planner → **إدارة حياتي** |
| «التنفيذ» (execute) | tasks, projects, goals, deepwork, work, calendar | كلها → **أنجز** (بلا تغيير تقريبًا) |
| «النمو» (growth) | health, reading, learning, brain | reading/learning/brain → **تطور** · health → **توازن** |
| «المجتمع» (community) | community | نقطة تنقل مستقلة (تُذاب كمجموعة) |
| «الحياة» (life) | finance, weekly-review, monthly-review, analytics | كلها + planner → **إدارة حياتي** |

## 4. التنقل — 5 نقاط للهاتف + الشريط الجانبي

### 4.1 شريط الجوال الجديد (يستبدل GlassNav الحالي)

| الموضع | البند | الوجهة | ملاحظة |
|---|---|---|---|
| 1 | **الرئيسية** 🏠 | `dashboard` (Home) | موجودة حاليًا |
| 2 | **استكشف** 🧭 | Explore Hub (جديد — المرحلة 18) | تستبدل مكان tasks |
| 3 | **+** ✨ | Quick Add bottom sheet (المرحلة 17) | زر مركزي بارز |

| 5 | **حسابي** ⚙️ | بطاقة حساب سريعة → `settings` | جديدة (تستبدل habits/planner) |

**القرار:** «tasks» و«habits» و«planner» تخرج من الشريط السفلي — ليس حذفًا لها بل نقلًا: المهام والعادات واليوم يعيشون في **Home/لقطة اليوم**، والوصول الشبكي عبر «استكشف». (الشريط الحالي 5 بنود مكتظ بوحدات؛ الجديد 5 بنود بأدوار هيكلية: مركز/استكشاف/إضافة/اجتماعي/ذات.)
- القيد الفني القائم (لا يتغير): 6 عناصر تفيض على شاشات 360px — 5 هو الحد الأقصى (ملاحظة glass-nav.tsx).

### 4.2 الشريط الجانبي لسطح المكتب (يُحدَّث في المرحلة 18)
- مثبّت: **الرئيسية** (أعلى) + **الإعدادات** (أسفل) — كما هو.
- المجموعات القابلة للطي → تصبح **4 بطاقات العوالم** بأسماء §3 بألوان هويتها (نفس تفاعل accordion القائم: `NAV_OPEN_KEY`، فتح تلقائي للمجموعة النشطة).
- صفحة **Explore Hub** (المرحلة 18): عرض العوالم كبطاقات كبيرة + بحث/command يفتح أي وحدة (⌘K موجود ويبقى مسار الوصول السريع الأول لسطح المكتب).
- مجموعة الأدمن تبقى كما هي (تظهر لـ role=admin فقط).

### 4.3 مسارات الوصول (كل وحدة ≤ 2 نقرة)
- سطح المكتب: Sidebar → عالم → وحدة (2) أو ⌘K → اسم الوحدة (1).
- الجوال: استكشف → عالم → وحدة (2) أو Home → عنصر اليوم (1) أو + → النوع (2).

## 5. قاعدة الـ 6 عناصر (Cognitive Budget)

> **القاعدة:** لا يظهر للمستخدم أكثر من **6 عناصر أساسية** في أي سياق واحد قبل «المزيد».

تطبيقاتها الملزمة:

| السياق | الحد | التطبيق |
|---|---|---|
| Home فوق الطية | 6 | الترتيب: تحية → تركيز اليوم → لقطة اليوم → أكمل من حيث توقفت → Quick actions → تقدمي. (Discover يُخفى خلف «المزيد»/أسفل الطية) |
| شريط الجوال | 5 | §4.1 |
| كل عالم في Explore | ≤6 | أنجز 6 · تطور 3 · توازن 4 · إدارة حياتي 5 — كلها ضمن الحد |
| قائمة الأوامر ⌘K | أول 6 نتائج | ثم تجميعات مقطعة |
| Quick Add sheet | 6 أنواع | مهمة · عادة · يومية · جلسة تركيز · هدف · ملاحظة/مرجع تعلم |
| بطاقة لقطة اليوم | 6 صفوف | ثم «عرض اليوم كامل» |
| الإشعارات | 5 غير مقروءة ثم «عرض الكل» | drawer الحالي |

**قاعدة الحكم عند التعارض:** عند إضافة عنصر جديد إلى سيق ممتلئ، يُحذف أو يُدمج عنصر قائم أولًا — لا نوسّع الميزانية الذهنية (هذا هو العلاج الهيكلي لملاحظة «كترت الخصائص»).

## 6. مصفوفة الحالات (Empty / Loading / Error / Success)

كل شاشة أساسية يجب أن تُصمَّم بحالاتها الأربع **قبل** بنائها. الحالة الافتراضية المرفوضة: شاشة فارغة بيضاء أو سبينر بلا سياق.

| الشاشة | Empty | Loading | Error | Success |
|---|---|---|---|---|
| **Home** | «يوم فارغ»: دعوة واحدة + 3 قوالب بداية | هيكل ثابت (skeleton للبطاقات فقط) | رسالة داخل البطاقة + إعادة محاولة، لا صفحة خطأ كاملة | تحديث بهدوء (لا confetti عام) |
| **My Day timeline** | «يومك فاضي — ابدأ بشيء واحد» | skeleton صفوف | إعادة تحميل القسم | نقل العنصر لحالة «تم» بهدوء |
| **Explore** | لا تنطبق (ثابتة) | فوري (بيانات محلية) | لا تنطبق | — |
| **Tasks** | «لا مهام اليوم — استرح أو خطّط» + زر إضافة (موجود) | skeleton قائمة | رسالة أعلى القائمة | مهمة تنتقل للأسفل بتلاشٍ ناعم |
| **Habits** | اقتراح 3 عادات بداية | skeleton حلقات | رسالة + retry | الحلقة تمتلئ (بدون رسالة نصية) |
| **Journal** | «اكتب أول يومية» + محفّز سؤال | skeleton | حفظ محلي مؤقت + إشعار | «تم الحفظ» toast قصير |
| **Deep Work** | شاشة جاهزة بالمؤقت مباشرة (لا empty أصلًا) | فوري | الجلسة لا تُفقد (حفظ محلي) | احتفال ختامي واحد (الموجود) |
| **Community** | «كن أول من يشارك اليوم» | skeleton بطاقات | رسالة feed | البوست يظهر أولًا |
| **Account/Settings** | لا تنطبق | skeleton أقسام | رسالة قسم | toast |
| **Admin** | جداول «لا نتائج» + فلاتر | skeleton جداول | بانر أعلى التبويب | toast + تحديث صف |

**القواعد العابلة للشاشات:**
1. لا تظهر شبكة skeleton كاملة أكثر من 400ms — بعدها هيكل ثابت هادئ.
2. كل Error يعرض: ما الذي فشل + سبب مفهوم + زر إعادة محاولة واحد واضح.
3. نجاح الكتابة = toast ≤ 2.5 ثانية أو تغيير بصري مباشر؛ لا نوافذ تهنئة متكررة.
4. حالات الصيانة/الجفاف (maintenance/offline) جاهزة من Task 36 وتحكمها `system/status`.

## 7. قواعد UX Copy (نبرة أوج)

المنتج مكتوب بالعربية الفصحى المبسطة مع مصطلحات تقنية إنجليزية كما هي (MCP، Focus…) — والنبرة الرسمية:

1. **فصحى واضحة قريبة** — جمل قصيرة، بلا عامية ثقيلة وبلا صياغة عقود قانونية في الواجهات.
2. **صفر لغة لوم:** ممنوع «فشلت/خسرت/كسرت سلسلتك». البدائل: «المتبقي»، «الفرصة التالية»، «يمكن اللحاق». (الإحساس بالتقدم = «اليوم يتحسن» لا «قيمتك».)
3. **صفر مبالغة تسويقية داخل التطبيق:** لا «ثوري/سحري/الأفضل في العالم». الوعود الواقعية فقط («خصوصيتك أولًا»، «يعمل بدون إنترنت جزئيًا»).
4. **أرقام عربية شرقية (٠١٢٣) في نصوص الواجهة** كما في المنتج حاليًا (٪٣٥) — الأرقام اللاتينية داخل أكواد/JSON/وقت تقني فقط.
5. **الأفعال قبل الأسماء في الأزرار:** «أضف مهمة» لا «إضافة مهمة»؛ «ابدأ الجلسة» لا «بدء».
6. **تعريف المصطلح عند أول ظهور** (سطر واحد): مثلاً «الدماغ الثاني — ملاحظاتك المرتبة بالمعنى».
7. رسائل الخطأ تتحمل المسؤولية: «تعذّر التحميل — جرّب تاني» لا «حدث خطأ فيك».
8. الحفاظ على التسميات الموحدة من `MODULE_LABELS` — أي تغيير اسم وحدة يمر من هناك فقط (منع التضارب الذي حسمته المرحلة 2).

## 8. قواعد Accessibility (الحد الأدنى الملزم)

الواقع الحالي من فحص الكود: 48 aria-label في وحدات rise · `prefers-reduced-motion` موجود في globals.css فقط · `focus-visible` مستخدم جزئيًا في ~5 ملفات · اختصارات لوحة مفاتيح موجودة (⌘K + ctrl+0/m/n/d + «/»). **السياسة:**

1. **حالة تركيز مرئية دائمًا** (`focus-visible` ring) على كل عنصر تفاعلي — Radix primitives تدير التركيز؛ ممنوع إزالة الـ ring بالـ CSS.
2. **لوحة المفاتيح مسار كامل** لكل مجرى أساسي: التنقل (⌘K موجود)، إضافة مهمة، بدء تركيز، حفظ يومية — كل زر قابل للوصول بـ Tab وEnter/Space.
3. **aria-label لكل زر أيقوني بلا نص** — الهدف: تغطية 100% من الأزرار الأيقونية الجديدة (48 الحالية تُراجع وتستكمل).
4. **التباين ≥ 4.5:1** للنص الأساسي و≥ 3:1 للنصوص الكبيرة/الأيقونات، على كل خلفيات glass الداكنة والفاتحة معًا.
5. **احترام `prefers-reduced-motion`:** كل حركة Framer Motion/spring تُغلَّف بشرط الحركة المخففة — تُعمَّم من globals.css إلى المستوى المطلوب (المؤقت والاحتفالات أولًا).
6. **أهداف لمس ≥ 44×44px** في شريط الجوال وصفوف القوائم.
7. **RTL منطقي لا فيزيائي:** الخصائص المنطقية (`ps/pe/ms/me` — النمط المستخدم في glass-nav `ltr:`/`rtl:`) في أي كود جديد؛ ممنوع left/right صريح.
8. **ترتيب عناوين دلالي** h1→h2→h3 لكل شاشة (يُختبر على الشاشات الجديدة عند بنائها).
9. قارئ الشاشة: اختبار أساسي (NVDA/VoiceOver) على Home وExplore وQuick Add عند اكتمال المرحلة 17/18 — مسجَّل في خطة التحقق §12.

## 10. تدقيق النقرات — الحالي ↔ الهدف

قياس تقديري من قراءة الكود (الأزرار الفعلية الموجودة: «مهمة جديدة» في tasks، بداية المؤقت في deep-work، check العادات في habits):

| المهمة الأساسية | الحالي (تقديري) | الهدف (عقد 17/18) |
|---|---|---|
| إضافة مهمة | شريط الجوال → المهام → «مهمة جديدة» → تعبئة → حفظ ≈ **4-5** | Home Quick action أو **+** → مهمة → حفظ = **2-3** |
| بدء جلسة تركيز | → العمل العميق → إعداد المدة → ابدأ ≈ **4** | Home «تركيز اليوم: ابدأ» = **2** |
| تسجيل عادة | → تتبع العادات → علِّم ≈ **3** | لقطة اليوم → علِّم مباشرة = **1** |
| كتابة يومية | → اليوميات → جديدة → اكتب → حفظ ≈ **4** | **+** → يومية → اكتب → حفظ = **3** |
| الوصول لأي وحدة بعيدة | فتح مجموعة الشريط → الوحدة ≈ **2-3** | استكشف → عالم → وحدة = **2** (أو ⌘K = **1**) |
| فهم حالتي اليوم | فتح 3-4 وحات ≈ **4+** | نظرة واحدة على Home = **0** |

**عقد الأداء المدرك (مع المرحلة 25):** LCP للـ Home تحت 2.5s على 4G، وطلبات أول تحميل ≤ نصف الحالي (حدود fold فقط — lazy لما تحتها).

## 11. مراجع التنفيذ للمرحلة التالية (17)

- **Home hierarchy النهائي:** Greeting → Focus of the Day → Today snapshot → Continue where you left off → Quick actions → Progress → (خلف الطية) Discover.
- حالات المستخدم التي تُصمَّم لها صراحة: جديد · يوم فارغ · يوم مزدحم · مساء · مستخدم تعلم-focused (نفس قائمة الخطة).
- Quick Add: bottom sheet على الهاتف (Vaul مرشّحة وفق سياسة المكتبات) / command popover على سطح المكتب — نفس نموذج البيانات.
- كل كلمة لوم تُمنع في Home (قواعد §7).
- مقاييس القبول: Playwright (Home loads for new/returning) · Quick Add ينشئ كيانًا واحدًا بلا طلبات مكررة · visual regression موبايل/ديسكتوب · قياس LCP/TTFB/طلبات أول render قبل/بعد.
