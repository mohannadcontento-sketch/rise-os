## 1. الغرض

تجميد الـScope قبل إعادة البناء حتى لا يصبح المشروع سلسلة من الإضافات غير المنتهية. هذه الوثيقة تجيب على الأسئلة الثمانية المطلوبة في مهام المرحلة صفر، وتغلق الأسئلة المعمارية الكبرى التي كانت ستوقف البدء.

**خط الأساس المستخدم:** النسخة الحالية تحتوي 25 واجهة مستخدم (‏`src/components/rise/`)‏ و51 مسار API (48 منها محمي بمصادقة)، مع 22 وحدة تُحمَّل تدريجيًا، و181 سياسة RLS في Supabase، ونظام XP وإنجازات يعمل، وPWA مكتملة. جودة الأمان إنتاجية فعلًا: Rate Limiting (‏5 محاولات ثم 429)، حماية CSRF (‏403 عند Origin أجنبي)، Security Headers كاملة، ومفاتيح Idempotency.

## 3. رحلة المستخدم — من التسجيل حتى الترقية

### 3.1 خريطة الرحلة (الإصدار الأول)

| المرحلة | ما يفعله المستخدم | ما يحدث في النظام | مؤشر النجاح |
|---|---|---|---|
| 1. الاكتشاف | يصل من بحث/مشاركة إلى awj.life | Landing تعرض القيمة + أسعار الخطط الثلاث | زائر ← تسجيل ≥ 8% |
| 2. التسجيل | بريد + كلمة مرور (الخطة Free افتراضيًا) | تسجيل + Rate Limiting + رسالة ترحيب | تسجيل ← أول دخول ≥ 90% |
| 3. Onboarding (3 خطوات) | الاسم، مجال التركيز، التفضيلات (وضع ليلي/إشعارات) | تجهيز لوحة اليوم بمحتوى بدئي | إكمال المعالج ≥ 70% |
| 4. أول قيمة (Aha) | يضيف أول مهمة وينجزها | ‏+10 XP + إشعار إنجاز | أول إنجاز خلال الجلسة الأولى ≥ 60% |
| 5. الحلقة اليومية | يفتح لوحة اليوم: مهام + عادات + نية اليوم | تذكيرات In-App (وWeb Push ضمن v1) | 3 أيام استخدام في أول 7 |
| 6. الترسيخ | streak عادات + مراجعة أسبوعية + XP تراكمي | شريط تقدم + إنجازات | ‏7 أيام متتالية ≥ 25% |
| 7. بلوغ الحد | يصل حد الخطة Free (انظر القسم 5) | ‏Paywall واضح + زر ترقية + عرض القيمة | حد ← ترقية ≥ 5% |
| 8. الترقية | يختار Plus أو Max | طلب ترقية + دفع يدوي (قسم 10) | تفعيل خلال ≤ 24 ساعة |
| 9. الاستمرارية | يراجع خطته، يشارك في المجتمع، يصدّر بياناته | تنبيهات تجديد الاشتراك قبل الانتهاء بـ7 أيام | شهري: احتفاظ مدفوع ≥ 85% |

### 3.2 لحظتان حاسمتان يجب حمايتهما تصميميًا

- **الأولى (دقيقة 0–5):** لا onboarding أطول من 3 خطوات، ولا شاشة فارغة — لوحة اليوم تُملأ بمهام مقترحة فورًا. المستخدم الذي لا ينجز مهمة في جلسته الأولى هو الأكثر عرضة للمغادرة.
- **الثانية (اليوم 7–14):** بلوغ الحد يجب أن يكون تجربة إيجابية: عرض استخدامك الحالي بوضوح (12/50 مهمة)، سبب الترقية، والبديل المجاني المتاح. لا paywall مفاجئ داخل فعل حساس.

### 3.3 نقاط احتكاك معروفة تُصلح قبل البيتا

- زر الصورة/اسم المستخدم يسجّل الخروج فورًا بلا قائمة تأكيد (‏`app/page.tsx:446` — وثّقه تقرير QA) → يُصلح في المرحلة 03.
- الحدود في v1 تُفحص server-side قبل كل عملية قابلة للعد (مبدأ الخطة) — لا عرض حد في الواجهة فقط.

## 4. قرار معماري مغلق: طبقات التخزين (قرار المالك — 11 سبتمبر 2026)

| الطبقة | التخزين | المحتوى | المبرر |
|---|---|---|---|
| **بيانات المستخدم الخاصة** | Supabase | ‏Auth + كل بيانات الإنتاجية (مهام/عادات/أهداف/يوميات) + الاشتراكات + الاستخدام + التفضيلات + صلاحيات MCP | عزل كامل بـRLS لكل مستخدم — المستخدم وحده يرى بياناته |
| **المجتمع (Community)** | **Turso من اليوم الأول** | المنشورات والتعليقات والإعجابات والقوالب العامة | **قرار المالك الصريح:** تخفيف الضغط عن Supabase وفصل مسار البيانات العامة منذ البداية — يُلغي توصية المراجع بتأجيل Turso |
| **الصور والمرفقات** | **Cloudflare R2** | صور الملفات العامة والخاصة ومرفقات المستخدم | **قرار المالك الصريح:** صفر رسوم egress + تكامل مباشر مع طبقة Cloudflare + تخفيف حِمل Storage عن Supabase |

**قواعد غير قابلة للتفاوض على الحدود الثلاث:**
1. أي حقل خاص لا ينتقل إلى Turso أبدًا — المجتمع مسار بيانات منفصل منذ التصميم.
2. الصور تُقدَّم عبر signed URLs من R2 (صلاحية مؤقتة) — لا تخزين صور في Supabase ولا روابط عامة دائمة للملفات الخاصة.
3. هوية المستخدم في Turso تُمرَّر كـuser_id فقط (UUID) — لا بريد ولا بيانات حساب.
4. تكلفة الطبقات الثلاث تدخل سطر التكاليف الشهري (بند «أضف سطر التكاليف» في رأي المراجع).

## 5. الخطط الثلاث وحدودها الأولية (تُبنى في المرحلة 04)

الحدود قابلة للتعديل قبل الإطلاق، لكن **البنية** (مصدر واحد + فحص server-side + عدّاد استخدام يومي/شهري) مُجمدة الآن.

| الحد / الميزة | Free ‏(0 ج) | Plus ‏(30 ج/شهر) | Max ‏(50 ج/شهر) |
|---|---|---|---|
| المهام النشطة | ‏50 | ‏500 | ‏5000 ضمن Fair Use |
| العادات المتتبعة | 5 | 20 | غير محدود |
| الأهداف النشطة | 3 | 15 | غير محدود |
| مشاريع (عند إطلاقها v1.1) | 1 | 10 | غير محدود |
| يوميات/شهر | 30 | 500 | غير محدود |
| سجلات الاستيراد/التصدير | 1/شهر | 10/شهر | 30/شهر |
| مساحة المرفقات (على R2) | 50MB | ‏1GB | ‏10GB |
| الإعلانات | خفيفة (مواضع القسم 6) | لا | لا |
| تذكيرات In-App | 3/يوم | غير محدودة | غير محدودة |
| Web Push | 1/يوم | 10/يوم | 30/يوم |
| المراجعة الأسبوعية | أساسية | أساسية + أرشيف | أساسية + أرشيف |
| المجتمع | قراءة + 3 منشورات/يوم | كامل | كامل |
| MCP | لا | لا | 8 أدوات (القسم 8) |
| دعم | مجتمعي | بريد خلال 48 ساعة | أولوية خلال 24 ساعة |

**قواعد الحدود (مُجمدة):**
1. الفحص في الـserver قبل أي عملية قابلة للعد (helper واحد — لا نسخ منطق داخل الميزات).
2. العدّاد يومي (`usage_daily`) + شهري (`usage_monthly`) كما في هيكل بيانات المرحلة 04.
3. بلوغ 80% من أي حد يطلق إشعارًا وديًا، وبلوغ 100% يطلق paywall مع عرض الترقية.
4. تغيير الفرونت لا يغيّر الحدود أبدًا — اختبارات اختراق للحدود ضمن Security Gate المرحلة 04.
5. قيمة Plus الواقفة (معالجة تحفظ رقم 8 في رأي المراجع): الحدود أعلى ×10 + بلا إعلانات + أرشيف + دعم — قيمة ملموسة دون MCP.

## 6. أماكن الإعلانات — للـFree فقط (تُبنى في المرحلة 08)

### 6.1 المواضع المسموحة (فقط، ولا يُضاف غيرها دون قرار مالك)

| الموضع | النوع | الحد الأقصى |
|---|---|---|

| نهاية قائمة المهام | بطاقة sponsored | 1 لكل قائمة |
| نهاية المراجعة الأسبوعية | بطاقة | 1 |

### 6.2 المحظور مطلقًا

- داخل: Onboarding، شاشات الدفع/الترقية، الإعدادات، أي Modal أو Dialog، ووضع التركيز.
- أي إعلان بيني (interstitial) أو منبثق (popup) في v1.
- أكثر من موضعين ظاهرين في الشاشة الواحدة.
- إعلان يحجب أو يؤخر فعلًا حساسًا (إضافة/إنجاز مهمة).

### 6.3 قواعد النظام

- المكوّن موحد (`AdSlot`) + مواضع ثابتة معرَّفة بالكود (Enum) — لا موضع ديناميكي.
- الـserver/entitlement layer يعرف أن Plus/Max لا يستقبلان وحدات إعلانية أصلًا (لا إخفاء CSS فقط).
- تشغيل/إيقاف + تاريخا بداية ونهاية + أولوية + حد impressions — الحقول جاهزة لإعلانات مباشرة لاحقًا.
- AdSense لا يُدخل قبل بيتا مغلقة مستقرة (تحفظ رقم 7 في رأي المراجع).

| **بيانات تشغيلية** | سجلات Rate Limiting، Audit Log لـMCP، عدادات الاستخدام | Supabase | الأدمن فقط (ضمن RLS) |

**قواعد غير قابلة للتفاوض:**
1. افتراض أي حقل: خاص. العلانية استثناء يتطلب opt-in صريحًا لحظة النشر (checkbox «انشر علنًا» مفلش افتراضيًا).
2. لا يجوز أبدًا قراءة جدول خاص لتغذية واجهة مجتمعية — مسار بيانات منفصل منذ التصميم.
3. الملف العام يعرض: الاسم + الصورة + نبذة — لا بريد، لا بيانات استخدام، لا إحصاءات خاصة.
4. حذف منشور مجتمعي = soft delete فوري + خروجه من كل الواجهات خلال دقيقة.

## 8. أدوات MCP المتاحة في Max — النسخة الأولى (تُبنى في المرحلة 09)

البنية موجودة جزئيًا (نظام مفاتيح API بتجزئة آمنة + 12 أداة معرَّفة لكن تنفيذها موقوف). القرار: 8 أدوات فقط في v1، قراءة أولًا:

| # | الأداة | النوع | الوصف |
|---|---|---|---|
| 1 | `list_tools` | قراءة | قائمة الأدوات المتاحة للمفتاح |
| 2 | `get_dashboard` | قراءة | ملخص لوحة اليوم (مهام/عادات/XP) |
| 3 | `get_tasks` | قراءة | مهام المستخدم مع فلتر الحالة |
