## 2. الأمان (بنود الخطة «Data / Security»)

- **فصل البيانات**: جداول المجتمع لا تحمل سوى `user_id` + معلومات العرض العامة (الاسم/handle/الصورة عبر RPC بصلاحيات موسّعة) — لا بريد ولا بيانات خاصة.
- **Ownership**: سياسات RLS — select (published أو صفك) / insert-own / update-own-published / delete-own. المحتوى المخفي يظهر لصاحبه فقط.
- **منع تزوير العدادات**: إذونات على مستوى **الأعمدة** — المستخدم يستطيع كتابة أعمدة المحتوى فقط (`title/body/edited_at`)؛ حتى نداء PostgREST مباشرة لا يستطيع تعيين `like_count`/`reply_count`/`status`. (اكتشفنا أثناء الاختبار أن Supabase default-ACL يمنح كل الصلاحيات تلقائيًا — سحبناها صراحة من `authenticated`).
- **Anti-spam**: rate limits في الـmiddleware (نشر 30/دقيقة، تعليقات 30، تفاعل 60، بلاغات 5) + قيود فريدة (تفاعل واحد/مستخدم/هدف، بلاغ واحد/مستخدم/هدف) + سقوف طول + dedup للإشعارات + حد 20 ذِكرًا للمحتوى الواحد.
- **سجل الإشراف**: كل إجراء يُقيَّد في `community_moderation_log` (قراءة/كتابة service_role فقط) + يُخطر المتأثر بإشعار عالي الأولوية.

## 3. الإشعارات (ربط الحدث الموحد)

| الحدث | النوع | لمن | dedup key |
|---|---|---|---|
| تعليق على منشوري | `community` | صاحب المنشور | `community-comment-<id>` |
| رد على تعليقي | `community` | صاحب التعليق الأب | `community-reply-<id>` |
| ذِكر في منشور/تعليق | `mention` (عالي) | المذكور | `mention-<source>-<id>-<uid>` |
| إخفاء/إزالة محتواي | `system` (عالي) | صاحب المحتوى | `mod-<action>-<id>` |
| حظر/فك حظر | `system` (عالي) | المستخدم | `mod-(un)ban-<uid>-<ts>` |

الإعجاب لا يولّد إشعارًا (قرار موثّق — مضاد للإزعاج). الأنواع `community`/`mention` كانت جاهزة منذ الهجرة 026 (CHECK + بوابة Push قسمتهما لفئة community)، فالـ Web Push يعمل لهذه الأحداث تلقائيًا لمن فعّل فئة المجتمع.

## 4. واجهة الاستخدام

- **وحدة «المجتمع»** في التطبيق (شريط جانبي + تنقل + بحث الأوامر): خلاصة بفلاتر، كومبوزر مع اقتراحات @mention منبثقة، تفاصيل منشور بتعليقات وردود، قلب toggle، بلاغ بحوار، تعديل/حذف ذاتي، **تحميل تدريجي** (IntersectionObserver + زر «المزيد») مع skeletons.

## 7. ملاحظة Turso

الخطة ذكرت «جداول المجتمع العامة إلى Turso» (قرار المالك — وثيقة النطاق §4). التنفيذ على مرحلتين:

1. **07 الأساسية:** جداول المجتمع في `public` بسفاراسيم البنية نفسها (RPC-only reads + service-writes + فصل منطقي: لا بيانات خاصة داخل جداول المجتمع).
2. **07-ب (المضافة):** **مرآة Turso فعلية مفعّلة بمفاتيح البيئة** — `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` في `src/lib/turso.ts` + طبقة `src/lib/community-sync.ts`: كل كتابة ناجحة في Supabase (منشور/تعليق/تفاعل/إشراف/تحديث ملف عضو) تنعكس فورًا إلى Turso (dual-write، fire-and-forget — فشلها لا يكسر الطلب أبدًا). المزامنة تغطي البيانات العامة فقط (members/posts/comments/reactions مع لقطة المؤلف وmedia)؛ البلاغات وسجل الإشراف والإشعارات = بيانات تشغيلية/خاصة تبقى في Supabase (وثيقة النطاق §7). القراءة تظل من Supabase حتى التحقق من المزامنة، ثم قلب `TURSO_READ_MODE` لاحقًا. للتعبئة الأولية: `bun scripts/turso-backfill.ts` (idempotent). اختبار طبقة المزامنة: `bun scripts/turso-local-test.ts` (12/12).

## 9. المرحلة 07-ب — التاب + الصور (R2) + الحصص (12 سبتمبر)

### 9.1 تاب المجتمع (إصلاح ملاحظة المالك «مش شايف تاب المجتمع»)
وحدة المجتمع كانت مبنية ومربوطة بالـstore/الصفحة/الأيقونة لكن **بلا أي مدخل تنقل** — عُلّيت:
- **الشريط الجانبي:** مجموعة «المجتمع» (بطاقة مستقلة، لون lime) بين «النمو والمعرفة» و«المال والمراجعة» — تُفتح تلقائيًا عند الانتقال العميق من إشعار.
- **شريط الموبايل السفلي (GlassNav):** المجتمع حلّ محل «المالية» في الخانات الخمس (المالية تبقى في القائمة الجانبية — 5 خانات فقط تتسع في شاشات 360px).
- **اختصار لوحة المفاتيح:** Ctrl+M للمجتمع (+ بطاقة في حوار الاختصارات).

### 9.2 صور المنشورات على Cloudflare R2 (قرار المالك — وثيقة النطاق §4)
- **التدفق:** زر إرفاق في الكومبوزر (حتى 4 صور، JPG/PNG/WebP/GIF، ≤ 8MB) → `POST /api/rise/community/media/presign` (401/zod/حصة/10 لكل دقيقة) → رفع PUT مباشرة من المتصفح إلى R2 عبر رابط موقّع (10 دقائق) — يتجاوز حد body الفيرسل 4.5MB.
- **الأمان:** المفتاح يولّد خادميًا (`community/<userId>/<uuid>.<ext>`)، صف `media_objects` (pending→active→deleted) يُكتب بـservice_role فقط (RLS: المستخدم يرى صفوفه)، وإرفاق media بالمنشور يتم عبر service_role بعد التحقق من الملكية والحالة (لا نثق بقوائم العميل — مرفق وهمي/مستخدم → 400 INVALID_MEDIA). **عمود media خارج إذونات أعمدة المستخدم** — تزويره مستحيل حتى عبر PostgREST مباشرة (مُثبت في الاختبار [2a]/[2b]).
- **التقديم:** الخادم يوقّع روابط قراءة مؤقتة (ساعة) عند إرجاع الخلاصة/التفاصيل — أو روابط عامة دائمة لو ضُبط `R2_PUBLIC_BASE_URL`. بدون مفاتيح R2: كل شيء يعمل نصيًا وزر الصور يعطي 503 عربيًا واضحًا (تدرّج آمن).
- **حصص التخزين** (وثيقة النطاق §5): 50MB مجانية / 1GB بلس / 10GB ماكس — مصدرها `plan_entitlements.storage_limit` (bigint — 10GB لا يتسع في INT اليومي)، والحساب = مجموع `pending+active`، والحذف الذاتي للمنشور يحرر الحصة (علامة deleted + حذف كائنات R2 best-effort). تجاوز الحصة → 402 STORAGE_LIMIT بنفس مسار upgrade prompt.

### 9.3 حد النشر اليومي (وثيقة النطاق §5: المجانية «قراءة + 3 منشورات/يوم»)
مسار النشر يستدعي `consume_usage('community.post')` قبل الإدراج — القرار الذري داخل DB (نفس آلية export/AI). عند المنع → 402 LIMIT_REACHED مع الاستخدام → واجهة upgrade prompt الموجودة تلتقطه. الحدود: مجاني 3/يوم و90/شهر، بلس/ماكس بلا حد يومي. عدّادات الاستخدام تظهر في الإعدادات تلقائيًا (`get_usage_overview` يقرأ plan_entitlements) مع تسمية «منشورات المجتمع».

### 9.4 الاختبارات (07-ب)
- **SQL على الإنتاج** (`supabase/tests/phase7b_media.sql`): **24/24** داخل ROLLBACK — CHECK بنية media (مفتاح/نوع/حجم/عدد)، anti-forgery (إذونات الأعمدة إدراجًا وتعديلًا)، RLS media_objects (أرى صفوفي فقط + لا كتابة للمستخدم إطلاقًا)، الحساب pending+active فقط، قيم الحصص للخطط الثلاث، حد 3/يوم عبر consume_usage (٣ مسموح → الرابع ممنوع)، RPCs تعيد media. بقايا صفر.

### 9.5 إجراءات المالك (تفعيل R2 وTurso — متغيرات بيئة في Vercel)
1. **R2 (الصور):** أنشئ Bucket + Access Key في Cloudflare ثم اضبط `R2_ACCOUNT_ID`/`R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY`/`R2_BUCKET` + قاعدة CORS تسمح بـPUT من نطاق التطبيق (التفاصيل خطوة بخطوة في `.env.example`). بعد التعيين مباشرة: زر الصور يعمل بلا أي نشر جديد.
